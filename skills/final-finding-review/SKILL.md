# Отбор итоговых разногласий

## Результат

Сформировать `/outputs/working/final-result.json` со схемой `conclusion.v1`.
Работать только с выводами готового `/outputs/working/analysis.json`.

Входы:

- `/outputs/working/analysis.json`;
- `/inputs/contract.txt`;
- `/inputs/matrix.json`;
- `references/selection-cookbook.md`.

Не менять analysis, не переставлять его статусы и не создавать новых findings.
Для каждой исходной записи возможно только два решения: перенести её в итоговый
протокол либо не переносить. Полные тексты договора и матрицы использовать для
проверки evidence и фильтров.

`main_idea` использовать как положительную подсказку о предмете строки матрицы.
Оно не заменяет полный текст, не является обязательным gate и не отменяет
доказанное расхождение, отсутствующее в `main_idea`.

## Workbook

### 1. Подготовить кандидатов

Выполнить:

```text
python /skills/final-finding-review/scripts/prepare_candidates.py --analysis /outputs/working/analysis.json --output /outputs/working/review-candidates.json
```

Скрипт механически исключает `aligned` и сохраняет исходные deviation, extra и
missing без изменения. Считать `review-candidates.json` исчерпывающим реестром:
не добавлять отсутствующие в нём группы.

### 2. Отобрать deviation

Для каждого кандидата со статусом `deviation`:

1. найти полный договорный пункт, связанные приложения и указанные строки
   матрицы;
2. проверить, подтверждаются ли исходные цитаты и различия полными текстами;
3. сопоставить каждое различие с одним конкретным классом `DEV-01`–`DEV-10` из
   cookbook;
4. применить исключения этого класса;
5. перенести группу, если хотя бы одно исходное различие подтверждено и проходит
   точный класс.

Для прошедшего различия должны быть названы:

- тема класса;
- юридический механизм;
- конкретный изменённый параметр.

Общая юридическая значимость, совпадение темы или одно слово «срок», «тариф»,
«риск», «инверсия» не заменяют точный класс. Если один аспект исключён, но
другой независимо проходит класс, сохранить только прошедший аспект.

Не менять исключённый `deviation` на `aligned`, `extra_in_contract` или
`missing_in_contract`: он просто не попадает в короткий протокол.

### 3. Отобрать mandatory missing

Для каждого `missing_matrix_item`:

1. проверить, что строка имеет `required_type: "mandatory"`;
2. проверить ограничения `only_for_product`, `only_for_lot`, `payment_method`,
   `only_for_terminal`;
3. установить применимость по оперативным условиям договора;
4. проверить отсутствие прямого, совокупного и корреспондирующего покрытия в
   договоре и относящихся приложениях;
5. применить границы MISSING cookbook.

Перенести missing только при одновременном выполнении всех условий. Если данных
недостаточно для исключения обязательного требования, считать его применимым.
Не переносить заголовок, optional либо требование, фактически покрытое другим
пунктом договора.

### 4. Отобрать extra

Для каждого кандидата со статусом `extra_in_contract`:

1. прочитать пункт в контексте раздела, внутренних ссылок и относящихся
   приложений;
2. проверить отсутствие прямого, совокупного и корреспондирующего аналога в
   матрице;
3. применить положительный критерий EXTRA cookbook.

Перенести extra только если пункт создаёт самостоятельное новое условие,
отсутствующее в матрице, которое:

- возлагает на Банк/Исполнителя обязанность;
- ограничивает право или усмотрение Банка;
- устанавливает ответственность, удержание или финансовое последствие для
  Банка;
- предоставляет контрагенту самостоятельное право требовать действие от Банка,
  уменьшить оплату, отказать Банку либо прекратить отношения.

Не переносить заголовки, глоссарий, реквизиты, описание предмета или цены без
нового требования, обязанности самого контрагента, декларацию о соблюдении
закона и стандартную закупочную формальность.

### 5. Сформировать conclusion.v1

Создать не более одного finding на исходный `contract_id`.

Для deviation:

- `contract_items[*].id` — исходный `contract_id`;
- `matrix_items[*].id` — `matrix_id` прошедшего различия;
- тексты и evidence — подтверждённые дословные цитаты исходного difference;
- `comment` — конкретное подтверждённое различие.

Если несколько различий одной группы прошли cookbook, сохранить их в одном
finding. Не включать исключённые различия.

Для extra использовать только `contract_items`, `comment` и evidence с
`contract_id`/`contract_quote`. Для missing использовать только `matrix_items`,
`comment` и evidence с `matrix_id`/`matrix_quote`.

```json
{
  "schema_version": "conclusion.v1",
  "completion_status": "complete",
  "findings": [
    {
      "status": "deviation",
      "contract_items": [
        {
          "id": "4.3",
          "text": "дословная цитата договора"
        }
      ],
      "matrix_items": [
        {
          "id": "2.1",
          "text": "дословная цитата матрицы"
        }
      ],
      "comment": "конкретное подтверждённое отличие",
      "evidence": [
        {
          "matrix_id": "2.1",
          "matrix_quote": "дословная цитата матрицы",
          "contract_quote": "дословная цитата договора"
        }
      ]
    }
  ]
}
```

Не создавать пустые поля и не включать `aligned`.

## Самопроверка

Перед завершением проверить:

- каждый finding существовал в `review-candidates.json` с тем же статусом;
- статус, ID и доказательства не получили нового юридического смысла;
- каждый deviation относится к конкретному классу cookbook и не попадает под
  его исключения;
- каждый missing является применимым mandatory без совокупного покрытия;
- каждый extra доказывает самостоятельное новое условие против Банка и не имеет
  аналога в матрице;
- `matrix_items[*].id` deviation совпадает с `evidence[*].matrix_id`;
- JSON синтаксически корректен и не содержит Markdown или постороннего текста.

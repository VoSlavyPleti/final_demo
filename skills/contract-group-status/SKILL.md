# Статусы зафиксированной карты сопоставлений

## Цель и границы

Прочитать `/inputs/contract.txt`, `/inputs/matrix.json` и
`/outputs/working/mapping.json`. Установить профиль договора, применимость каждой строки
матрицы и статусы всех зафиксированных групп. Сохранить результат в
`/outputs/working/status.json`.

Считать mapping неизменяемым: не добавлять и не удалять группы или связи, не менять
их порядок, `contract_id`, `contract_locator`, `matrix_ids` и `mapped_scope`. Не формировать
итоговый протокол.

## Профиль и применимость

1. Установить по преамбуле, предмету, правам, обязанностям и реквизитам алиасы `Банка` и
   `Предприятия`.
2. Установить закупочные режимы, продукты, способы оплаты и типы терминалов. Опираться на
   выбранную опцию, предмет, тариф, спецификацию или оперативное право или обязанность.
   Не выводить применимость из одного термина в глоссарии, пустого поля, неотмеченного чекбокса или
   технической возможности. В частности, способность дисплея показывать QR-код не доказывает использование QR.
3. Оценивать непустые selector-поля `only_for_lot`, `only_for_product`, `payment_method` и
   `only_for_terminal` как OR внутри каждого массива и как AND между полями. Пустой массив не
   ограничивает применимость.
4. Присваивать `not_applicable` только при доказанном несовпадении хотя бы одного непустого selector-поля.
   При недостатке данных считать требование применимым и указать неопределённость в причине.
5. Строку с `required_type: null` считать структурной: она не образует самостоятельного mandatory-требования.

## Статус contract-oriented группы

Оценивать один исходный пункт договора относительно совокупности его применимых кандидатов:

- `extra_in_contract` — `matrix_ids` пуст; наличие или отсутствие самостоятельного обязательства не меняет
  этот внутренний статус, но фиксируется отдельным полем;
- `not_applicable` — `matrix_ids` непуст, но ни один кандидат не применим к текущему договору;
- `aligned` — применимые кандидаты совместно покрывают всё относящееся юридически значимое содержание
  без изменения существенных элементов;
- `deviation` — хотя бы один применимый юридический аналог есть, но относящаяся сторона, действие,
  объект, адресат, объём, основание, триггер, способ, условие, срок или сумма отсутствует, добавлена,
  изменена, ограничена или инвертирована.

В `evaluated_matrix_ids` копировать только применимые ID из исходного `matrix_ids`, сохраняя их
порядок. Не учитывать неприменимый кандидат при выборе `aligned` или `deviation`.

Для каждого `extra_in_contract` прочитать полный пункт и зафиксировать:

- `source_kind`: `main_body`, `appendix`, `glossary`, `heading`, `requisites` или `technical_or_reference`;
- `independent_legal_obligation: true` только для самостоятельного права, обязанности, ограничения или
  ответственности. Определение, заголовок, реквизит, поле формы, техническое описание и справочный текст такого
  эффекта не создают.

Пункты приложений не попадают в итоговую extra-категорию, но обязательно читаются при статусной оценке
основного пункта, который на них ссылается.

## Приоритетные элементы сравнения

Для одного и того же правоотношения считать конкретную обязанность, срок, дату, период, сумму,
процент, формулу, расчётную базу, единицу измерения и событие начала отсчёта обязательным эталоном.
Любое отличие, включая отсутствие, добавление и более выгодное для Банка значение, даёт `deviation`.

Не сравнивать число или обязанность из другого правоотношения. Пустой шаблонный параметр матрицы не
является конкретным эталоном. Выбор одной из прямо разрешённых матрицей альтернатив сохраняет `aligned`.

Прямая применимая ссылка на 44-ФЗ или 152-ФЗ может покрывать непосредственно включённое ею обязательное
содержание. Она не покрывает специальные срок, сумму, ставку, роль, способ или защиту Банка. Явно противоречащее
условие всегда применять вместо общей ссылки на закон.

## Классификация матричных строк

Создать в `matrix_review` ровно один объект для каждого исходного `number` матрицы в её порядке:

- `structural` — `required_type` отсутствует;
- `not_applicable` — строка не применима по selector-полям;
- `mapped` — строка применима и её ID присутствует хотя бы в одном `mappings[].matrix_ids`;
- `missing_in_contract` — строка применима, её ID входит в `missing_matrix_ids`, а `required_type` равен `mandatory`;
- `optional_absent` — строка применима, её ID входит в `missing_matrix_ids`, а `required_type` равен `optional`.

`missing_matrix_ids` означает только отсутствие аналога до фильтра применимости. Не переносить его автоматически
в `missing_in_contract`.

## Калибровка и проверка фактов

До классифации прочитать
`/skills/status/contract-group-status/references/calibration.md`. Для каждой группы выбрать наиболее близкую
аналогию по механизму, объекту, основанию и изменяемому элементу. Применять антипримеры для защиты от
ложного `deviation`. Не использовать калибровку для исправления mapping.

Перед каждым `deviation` повторно прочитать полный пункт договора и все оцениваемые пункты матрицы.
Каждое утверждаемое отличие должно прямо присутствовать в обоих источниках. Если оно не подтверждается, удалить
его из коммента и пересмотреть статус.

## Формат рабочего артефакта

Сохранить `/outputs/working/status.json` как чистый валидный JSON:

```json
{
  "completion_status": "complete",
  "contract_profile": {
    "bank_aliases": ["Исполнитель"],
    "counterparty_aliases": ["Заказчик"],
    "lot_regimes": ["fz_44"],
    "products": ["trade_acquiring"],
    "payment_methods": [],
    "terminal_types": ["pos"],
    "evidence": [
      {"locator": "п. 1.1", "quote": "Дословный фрагмент"}
    ]
  },
  "groups": [
    {
      "contract_id": "1.1",
      "contract_locator": "Основной текст, п. 1.1",
      "matrix_ids": ["3.1"],
      "mapped_scope": [
        {
          "matrix_id": "3.1",
          "contract_scope": "…",
          "matrix_scope": "…"
        }
      ],
      "evaluated_matrix_ids": ["3.1"],
      "status": "aligned|deviation|extra_in_contract|not_applicable",
      "comment": "",
      "source_kind": null,
      "independent_legal_obligation": null
    }
  ],
  "matrix_review": [
    {
      "matrix_id": "2.1",
      "required_type": "mandatory|optional|null",
      "applicability": "applicable|not_applicable|structural",
      "coverage_status": "mapped|missing_in_contract|optional_absent|not_applicable|structural",
      "reason": "Краткое фактическое обоснование"
    }
  ]
}
```

Для `extra_in_contract` заполнять `source_kind` и `independent_legal_obligation`; для остальных статусов ставить
оба поля в `null`. Для `aligned` оставлять `comment` пустым. Для `deviation` кратко приводить оба подтверждённых
значения или условия в форме «Матрица: …; договор: …». Для `extra_in_contract` кратко фиксировать отсутствие аналога и
самостоятельный правовой эффект.

Перед завершением проверить:

- равенство числа и порядка `groups` и входных `mappings`;
- дословную неизменность mapping-полей;
- ровно одну строку `matrix_review` для каждого исходного `number` матрицы;
- допустимость каждого статуса и согласованность `matrix_review` с mapped/missing-разбиением;
- равенство `evaluated_matrix_ids` применимому подмножеству исходных `matrix_ids`;
- наличие дословного доказательства для каждого пункта профиля и каждого заявленного отличия.

Устанавливать `completion_status: "complete"` только после этой проверки.

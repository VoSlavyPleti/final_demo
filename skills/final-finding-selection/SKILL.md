# Отбор итоговых разногласий

## Назначение

Прочитать только `/outputs/working/complete-analysis.json` и записать
`conclusion.v2` строго в `/outputs/working/final-result.json`.

Complete analysis является исчерпывающим источником решений и цитат. Не читать
исходный договор или матрицу, не выполнять mapping, не менять статусы и не
добавлять новое разногласие.

Перед отбором прочитать `references/materiality.md`.

## Источники кандидатов

Рассмотреть:

- каждую contract-группу со статусом `deviation`;
- каждую contract-группу со статусом `extra_in_contract`;
- каждую запись `matrix_audit` с `resolution: "missing_in_contract"`.

Не рассматривать aligned, mapped, recovered, optional_absent и not_applicable
как самостоятельные findings.

## Отбор deviation

Включить deviation, только если зафиксированное upstream отличие соответствует
одному из классов ниже и меняет юридический или операционный результат,
конкретный обязательный параметр либо позицию Банка:

- `amount_or_rate`;
- `deadline_or_date`;
- `bank_right`;
- `bank_restriction`;
- `payment_mechanism`;
- `trigger`;
- `channel_or_form`;
- `required_scope`;
- `data_transfer`;
- `other_material`.

Название класса само по себе не является основанием для включения. Определять
класс только по `differences`, полным текстам и цитатам complete analysis. Не
исправлять слабую связь и не создавать новую причину.

Если одна группа содержит несколько связанных различий, сформировать один
finding и выбрать наиболее специальный либо наиболее существенный
`issue_class`. В комментарии перечислить остальные подтверждённые параметры.

## Отбор missing

Включить каждую запись, у которой одновременно:

- `required_type: "mandatory"`;
- `applicability: "applicable"`;
- `resolution: "missing_in_contract"`.

Не применять к такой записи дополнительный фильтр материальности: полнота и
применимость уже установлены recovery-этапом.

## Отбор extra

Включить extra только при наличии в `contract_text` и `extra_reason`
самостоятельного условия против Банка:

- новой обязанности Банка;
- ограничения или запрета права Банка;
- самостоятельного права контрагента требовать действие, отказаться от
  приёмки или прекратить отношения;
- штрафа, удержания, уменьшения оплаты, возмещения или иной ответственности
  Банка;
- отдельной операционной процедуры, отсутствующей в матрице и обременяющей
  Банк.

Исключить заголовки, определения, реквизиты, описание предмета или цены,
закупочные и законодательные декларации без нового операционного эффекта,
обязанности самого контрагента и пояснительный текст.

Не считать самостоятельным extra условие, которое лишь повторяет установленное
законом право стороны либо общую гарантию качества без специального срока,
суммы, санкции или ограничения Банка.

## Объём

Не обрезать доказанные findings по числу. Ожидать до 25 пунктов в обычном
договоре, но сохранить все записи, прошедшие критерии.

## Формат `conclusion.v2`

```json
{
  "schema_version": "conclusion.v2",
  "completion_status": "complete",
  "findings": [
    {
      "status": "deviation|missing_in_contract|extra_in_contract",
      "issue_class": "amount_or_rate|deadline_or_date|bank_right|bank_restriction|payment_mechanism|trigger|channel_or_form|required_scope|data_transfer|other_material",
      "contract_items": [
        {
          "id": "5.3.15",
          "locator": "п. 5.3.15",
          "text": "полный текст пункта договора"
        }
      ],
      "matrix_items": [
        {
          "id": "4.2.16.3",
          "text": "полный текст строки матрицы"
        }
      ],
      "comment": "конкретное отличие или отсутствующее/дополнительное условие"
    }
  ]
}
```

Для missing установить `contract_items: []`. Для extra установить
`matrix_items: []`. Не выводить уровень риска, aligned-группы, Markdown или
текст вне JSON.

## Самопроверка

Перед `completion_status: "complete"`:

1. Убедиться, что каждый finding существует в complete analysis с тем же
   статусом.
2. Убедиться, что каждый mandatory applicable missing перенесён.
3. Убедиться, что каждый deviation проходит конкретный класс reference.
4. Убедиться, что каждый extra содержит самостоятельное обременение Банка.
5. Убедиться, что ID и полные тексты скопированы без изменения смысла.
6. Повторно прочитать итоговый JSON.

# Точечное восстановление полноты матрицы

## Назначение

Прочитать:

- `/outputs/working/primary-analysis.json`;
- `/inputs/contract.txt`;
- `/inputs/matrix.json`.

Записать `complete-analysis.v1` строго в
`/outputs/working/complete-analysis.json`. Считать primary-артефакт исходным
графом. Не выполнять повторный полный contract-first анализ и не пересматривать
уже согласованные aligned-связи.

Перед началом recovery прочитать `references/calibration.md`.

## Рабочие строки матрицы

Считать рабочей каждую строку с непустым `required_type`. Строки без
`required_type` являются структурными заголовками и не входят в
`matrix_audit`.

Сформировать множество matrix ID из всех `candidates` primary-групп и построить
точечную очередь:

1. рабочие matrix ID, отсутствующие во всех кандидатах;
2. matrix ID конкретных `differences` с `kind: "absent"`;
3. все primary-группы со статусом `extra_in_contract`.

Не отправлять на recovery явные `changed`, `inverted` или
`additional_obligation` для снятия риска.

## Применимость

Использовать `contract_profile`, полный договор и флаги строки:

- `only_for_product`;
- `only_for_lot`;
- `payment_method`;
- `only_for_terminal`.

Подтверждать применимость продукта оперативной обязанностью, выбранным тарифом,
заполненным параметром подключения или фактическим порядком операций.
Определение, пустой чекбокс, перечень технических возможностей или одиночное
упоминание не подтверждают продукт.

При доказанной неприменимости установить `not_applicable`. При недостатке
данных для исключения mandatory считать строку применимой.

Optional без аналога получает `optional_absent`. Если optional имеет сильный
аналог, анализировать его как обычное требование.

## Recovery строки матрицы

Для каждого непокрытого или absent-аспекта:

1. Прочитать полный текст строки и `main_idea`.
2. Использовать `main_idea` только как положительный ориентир.
3. Искать прямой механизм по всему договору.
4. Проверить фрагментированное покрытие несколькими пунктами.
5. При отсутствии прямого аналога проверить корреспондирующее право или
   обязанность.
6. Затем проверить настоящую инверсию того же действия.
7. Не принимать общую тему, общий срок, сумму или экономический эффект за
   юридический аналог.

При найденных кандидатах добавить связь в каждую затронутую contract-группу с
полным `matrix_text` и дословными `matched_aspects`. Не расширять другие
группы, которые не относятся к проверяемому остаточному требованию.

Если дополнительный пункт закрывает `absent`, удалить только это отличие.
Удаление допустимо только когда в эту группу добавлен кандидат с дословной
договорной цитатой, закрывающей именно названное отсутствующее требование, а
основание записано в `recovery_notes`. Нельзя снимать `absent` выводом о
неприменимости части уже сопоставленной строки либо общим утверждением о
покрытии. Если после доказанного удаления отличий их не осталось, изменить
статус затронутой группы на `aligned`. Явное противоречащее условие не снимать
другой согласованной формулировкой.

Существующие `changed`, `inverted` и `additional_obligation` неизменяемы на
этом этапе. Если после recovery в группе остаётся хотя бы одно отличие, её
статус остаётся `deviation`.

## Перепроверка preliminary extra

Для каждой extra-группы повторно искать сильный аналог по всей матрице.

- При найденном аналоге добавить кандидата и заново определить статус только
  этой группы.
- При совпадении без отличий установить `aligned`.
- При отличии того же механизма установить `deviation`.
- Оставить `extra_in_contract` только при отсутствии прямого, совокупного,
  корреспондирующего или инвертированного аналога.

Не считать реквизит, глоссарий или заголовок extra. Если такая запись ошибочно
попала в primary-группы, оставить её вне итоговых findings и объяснить
структурную ошибку в `recovery_notes`.

## Решение по остаточной строке

| Условие | `resolution` |
|---|---|
| ID уже имеет сильный primary-кандидат | `mapped` |
| Кандидат найден на recovery | `recovered` |
| Применимый mandatory остался без кандидата | `missing_in_contract` |
| Применимый optional остался без кандидата | `optional_absent` |
| Механизм доказанно неприменим | `not_applicable` |

`missing_in_contract` недопустим при наличии сильного кандидата в любой
contract-группе.

## Формат `complete-analysis.v1`

```json
{
  "schema_version": "complete-analysis.v1",
  "completion_status": "complete",
  "contract_profile": {},
  "groups": [],
  "matrix_audit": [
    {
      "matrix_id": "4.2.13",
      "matrix_text": "полный текст строки",
      "required_type": "mandatory|optional",
      "applicability": "applicable|not_applicable",
      "resolution": "mapped|recovered|missing_in_contract|optional_absent|not_applicable",
      "contract_ids": [],
      "reason": "краткое основание только для recovery, missing или not_applicable"
    }
  ],
  "coverage_audit": {
    "working_matrix_count": 0,
    "mapped_count": 0,
    "recovered_count": 0,
    "missing_count": 0,
    "optional_absent_count": 0,
    "not_applicable_count": 0,
    "unresolved_matrix_ids": []
  },
  "recovery_notes": []
}
```

Скопировать `contract_profile` и все primary-группы, применив только доказанные
точечные исправления. Для `mapped` не повторять рассуждение: достаточно ID
связанных contract-групп. Для missing сохранить полный `matrix_text` и
конкретное непокрытое требование в `reason`.

Не добавлять Markdown или текст вне JSON.

## Самопроверка

Перед `completion_status: "complete"`:

1. Сравнить множество рабочих ID матрицы с `matrix_audit`.
2. Убедиться в отсутствии пропусков и дублей.
3. Убедиться, что каждый recovered ID появился в кандидатах группы.
4. Убедиться, что ни один missing ID не имеет сильного кандидата.
5. Убедиться, что устранённый `absent` действительно покрыт относящимся
   договорным положением, добавленным кандидатом и дословной цитатой, и
   объяснён в `recovery_notes`.
6. Убедиться, что `unresolved_matrix_ids` пуст.
7. Повторно прочитать итоговый JSON.

Если полную очередь нельзя разрешить, не устанавливать `complete` и завершить
работу сообщением об ошибке.
